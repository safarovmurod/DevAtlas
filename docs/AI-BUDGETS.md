# Durable online Tutor budgets

Local course answers remain free and require no provider. Online AI requires verified account/MFA, the server provider key, the budget migration and explicit nonzero server budgets. Missing configuration, failed storage or exhausted budgets stops the request **before** provider dispatch. Defaults in `.env.example` are zero/false. This does not activate a paid service.

Apply `supabase/migrations/20261026010000_tutor_budgets.sql` to an approved test database after the account migrations. Its two RLS-enabled tables are inaccessible to guests and learners. Only the service role can execute the reservation function; the caller user ID comes from verified server authentication. A PostgreSQL advisory transaction lock covers both global and user checks/writes, including a three-second user cooldown. Daily windows use the database's UTC date, across restarts and application instances.

Set server-only `AI_DAILY_BUDGET_MICROUSD`, `AI_USER_DAILY_BUDGET_MICROUSD`, `AI_USER_DAILY_REQUEST_LIMIT`, `AI_MAX_MICROUSD_PER_TOKEN` and `AI_PROVIDER_USAGE_BOUND_CONFIRMED` only after approving the limits and verifying the selected provider/model's billing rules. MICROUSD means one millionth of USD. A positive **integer ceiling** per token may deliberately overestimate fractional rates. No real key or spending authorization is supplied by this change.

Each call reserves a conservative upper bound: UTF-8 bytes of serialized messages, 64 framing tokens per message and 256 output tokens, multiplied by the configured maximum token rate. Confirm that the chosen byte-token model stays within this input bound, and that the provider enforces `max_tokens` across **all billable output and reasoning**. If those guarantees cannot be established, keep the confirmation false and online AI disabled. Different tokenizer/billing semantics require a reviewed adapter, not a guessed price.

Reservations are charged in full, including provider errors/timeouts. There is no refund based on untrusted or absent usage: a lost response does not prove no work was billed. The budget is therefore a conservative spending ceiling, not an invoice/actual-cost display. Provider-side hard spend limits should also be configured. Lowering a limit below the day's existing reservations prevents further calls. Raising limits is an operator configuration change.

Tests run the real migration in local PGlite/PostgreSQL: denied/rollback cases, shared global ceiling, per-user limits, rate enforcement, UTC window separation and privilege denial. Route/unit tests mock only authentication/provider/database transport and explicitly check that denied reservations make no provider call. They do not verify live Supabase or AnyModel. Production migration/provider credentials/billing bounds are **BLOCKED** in this workspace; no live migration or charged request is claimed.

Site Agent history remains local, validated and separated by account/guest. The legacy global key is retained without automatic ownership assignment. This is not server history or encryption against other people who can inspect the same browser profile. Shared multi-conversation history is still TODO.
