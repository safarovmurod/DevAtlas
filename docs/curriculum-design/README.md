# Short-course authoring blueprints — not published lessons

`short-courses.draft.json` covers all twelve required short courses. It records each existing lesson identity, the intended learning sequence, module outcomes and deliverables, capstone criteria, and source-review work. It is editorial design data outside `src/content/courses`; the application does not import it. Nothing here adds a published day, completes a course or grants Verified status.

Validate identities, coverage and references with `node scripts/check-short-course-blueprints.mjs`. This structural check is not a teaching-quality certificate. The real catalog/coverage reports remain authoritative for published counts.

Backend and Mobile need preparation in JavaScript/React as well as their subject, so the draft includes 44 distinct days each. English has 42; broad general subjects have 30. Personal Productivity has 22 distinct competencies rather than padded repeats. These are authoring proposals, not arbitrary publication targets: revise duration if actual explanation/practice requires it. Existing first days are retained but must be deepened into genuinely beginner-accessible guided introductions before expansion is published.

The research registry distinguishes selected-source review from candidates and retained links. Official Node 24 HTTP documentation was downloaded; React Native and W3C introductory sources were read, and OpenStax collection structure/license metadata was inspected. This does not mean entire books or every planned claim have been researched. React Native's introductory upstream file warns about legacy APIs; confirm stable Core Components and an actual compatible Expo/RN release before examples are authored. Mobile build results must be executed, not inferred from source presence.

The inspected OpenStax marketing, management, entrepreneurship and writing collections are CC-BY-NC-SA 4.0. They are references for factual research and ordering; do not copy their prose, distinctive examples or media into the commercial platform. Author original explanations, cases and exercises. College Success's inspected collection declares CC-BY 4.0; other candidate/license details still need verification before reuse. URLs alone are not proof of source review. British Council direct access currently fails at the environment's CONNECT proxy (403); pronunciation/CEFR claims remain unverified and must not be invented.

For each lesson, review the relevant official sources and versions, write complete original RU/TG/EN teaching, add a subject-appropriate demonstration, guided/independent practice, progressive hints, meaningful feedback, 5–10 non-duplicated checks and retry variants. Implement projects and real assessments, execute supported examples, and update catalog/localization/tests/reports only when those actual lessons are ready. Written rubrics stay Self Reviewed until genuine authorized review exists; a planned human-review step is not a delivered human review. Paid access stays server-controlled and independent of readiness.

The existing JSON curricula are the starting material, not a reason to duplicate days or overwrite progress. Preserve IDs, useful material, drafts and notes. Full Learn → Understand → Watch → Try → Practice → Test → Review → Master adoption and custom non-HTML demonstrations still require implementation for these subjects. Do not use an HTML DOM visualizer as a generic substitute for UX, marketing, English or management.
