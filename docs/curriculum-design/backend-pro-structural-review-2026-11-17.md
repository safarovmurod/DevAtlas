## Курс и его контракт

- 30 дней, все `practice.kind = 'code'`, ни одного written-дня. Секции на день: 4 или 5 (минимум 4 — контракт соблюдён до правок).
- Технология курса: Node.js без фреймворков — `node:http` (`createServer`, `writeHead`, `requestTimeout`/`headersTimeout`), `node:crypto` (`scryptSync`, `timingSafeEqual`, `createHmac`, `randomBytes`, `createHash`), `node:assert/strict`, `fetch`, `AbortController`, cookie-атрибуты, JWT-механика, mock-репозиторий вместо БД. Express и PostgreSQL курсом не используются — поэтому документация expressjs.com и postgresql.org не запрашивалась (это честно зафиксировано ниже как «не запрошено, потому что не относится»).
- Trust-example дизайн: у всех 30 дней `practice.solution === example.code` (байт-в-байт с `sections[1].code`, у дня 1 — `sections[1].code`). Это разрешённая схема для backend-pro (тест `premium-curriculum.test.ts` «trusted examples execute and produce their stated output»); solutions не тронуты ни в одном дне.

## Что исправлено

### 1. Третий вопрос `backend-pro-day-NN-q3` на все 30 дней

Каждый новый вопрос: id по шаблону курса (дни 1–3: `backend-pro-day-0N-q3`; дни 4–30: `backend-pro-day-NN-q3`), ровно 3 варианта, дистракторы — реальные ошибки новичка («JavaScript считает длину строки в байтах», «200 — гости читают публичные задачи», «GET всегда медленнее остальных методов из-за кэша», «timingSafeEqual шифрует значение перед сравнением», «Ничего: payload скрыт подписью», «Очередь дублирует задания для надёжности», «HTTP сам перенаправит запрос на первый инстанс» и т. п.), `hint` (наводящий, не раскрывающий ответ) и `relatedSection`, указывающий на раздел, который учит ответу. `answer` — короткое пояснение в трёх языках. Формулировки проверяют понимание («Что вернёт…», «Почему…», «Что произойдёт…», «Какой порядок…»). Ничего не скопировано из существующих вопросов; существующие id, формулировки, варианты и `correctIndex` не тронуты (проверено deep-compare против `git show HEAD`).

Темы q3 по дням: 1 — байты UTF-8 против длины строки; 2 — 401 гостя до запроса к базе; 3 — что видит интеграционный тест; 4 — изменения через GET; 5 — limit=999 сжимается до 50; 6 — маскировка приведения типов; 7 — 500 за невалидный ввод; 8 — timing-утечка при сравнении хешей; 9 — base64url читается без ключа; 10 — порядок 401→403→404→200; 11 — SameSite=None требует Secure; 12 — экранирование при каждом выводе; 13 — тавтология в WHERE; 14 — requestId вместо фрагмента токена; 15 — обязательные поля записи лога; 16 — лимитер per-instance; 17 — повтор с тем же ETag; 18 — что доказывает проверка после отката; 19 — backfill при expand; 20 — env-переменные всегда строки; 21 — очистка таймера в finally; 22 — умножение ретраев по слоям; 23 — 4xx зависимости при fast-fail; 24 — двойная обработка задания; 25 — «health 200 + ready 503»; 26 — жёстко прописанный порт; 27 — путь без fallback; 28 — 51 запрос N+1; 29 — сессия в памяти одного инстанса; 30 — порядок обработки capstone.

`correctIndex` новых вопросов: на днях с различающейся парой использовано недостающее значение из `{0,1,2}`; на днях с дублирующейся парой — поочерёдно 0/1/2 без постоянного паттерна. Существующие пары по факту: `(1,1)` дни 1, 12, 22, 29 → новые 0, 0, 0, 2; `(0,0)` дни 15, 17, 25, 26 → новые 2, 1, 2, 1. Первичный план для дней 8, 16, 28 был сверен по фактическим парам `(1,2)`, `(1,0)`, `(0,1)` и скорректирован скриптом-самопроверкой до применения (без записи файла). ## Источники (открыты и прочитаны 2026-11-17)

Новый текст (RU/TG/EN) написан заново; источники подтверждают фактические утверждения в подсказках/ответах/пояснениях. Выбраны те источники, которые объявлены в `sources` курса и которые курс фактически использует:

- https://nodejs.org/api/http.html (WebFetch) — подтверждены: `http.createServer` + requestListener, `IncomingMessage`/`ServerResponse`, `response.writeHead(statusCode, headers)` и обязательный `response.end()`, `message.headers` (имена в нижнем регистре), `server.requestTimeout` (408 при истечении) и `server.headersTimeout`. Статусы 405/413/429 и Allow/Retry-After на этой странице отсутствуют — они взяты из RFC (ниже).
- https://nodejs.org/api/net.html (WebFetch) — подтверждены: «If port is omitted or is 0, the operating system will assign an arbitrary unused port, which can be retrieved by using server.address().port after the 'listening' event»; `listen(port, host)` привязывает к указанному адресу (127.0.0.1); `server.address()` возвращает `{ port, family, address }`.
- https://nodejs.org/api/crypto.html — страница большая, WebFetch дважды обрезал её до X509Certificate; затем страница получена целиком через curl и факты взяты точными grep-цитатами из самой страницы: «Scrypt is a password-based key derivation function that is designed to be expensive computationally and memory-wise in order to make brute-force attacks unrewarding», параметры `cost`/N (CPU/memory cost, степень двойки, default 16384), `blockSize`/r (default 8), `parallelization`/p (default 1), `maxmem` («Memory upper bound… error when 128 * N * r > maxmem», default 32 MiB); `timingSafeEqual` — «does not leak timing information that would allow an attacker to guess one of the values», буферы «must have the same byte length. An error is thrown if a and b have different byte lengths»; `randomBytes` — «size <number> The number of bytes to generate», «Generates cryptographically strong pseudorandom data»; `createHmac('sha256', secret)` — HMAC с алгоритмом и ключом.
- https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Set-Cookie (WebFetch) — подтверждены: HttpOnly «Forbids JavaScript from accessing the cookie» (но cookie всё равно отправляется с JS-инициированных запросов — это прямо учтено в тексте дня 11), Secure (только https, исключение localhost), SameSite=Lax («top-level navigation + safe method» — уточнение против формулировки «только GET»), SameSite=None «The Secure attribute must also be set», Max-Age в секундах.
- https://developer.mozilla.org/en-US/docs/Web/API/fetch (WebFetch) — подтверждён `AbortError` DOMException при вызове `AbortController.abort()`.
- https://developer.mozilla.org/en-US/docs/Web/API/AbortController и …/AbortController/abort (WebFetch) — подтверждены: `signal` для связи с операцией, `abort(reason)` («The reason why the operation was aborted… If not specified, the reason is set to 'AbortError' DOMException»), abort способен прервать fetch до завершения. Деталь «abort после завершения — no-op» на этих страницах явно не сформулирована (перенесена на AbortSignal-страницу) — в текст урока это утверждение не добавлялось.
- https://httpwg.org/specs/rfc9110.html (curl + точные цитаты) — подтверждены: 405 «The origin server MUST generate an Allow header field in a 405 response containing a list of the target resource's currently supported methods»; 413 Content Too Large; Retry-After (10.2.3) «indicate how long the user agent ought to wait… value can be either an HTTP-date or a number of seconds»; идемпотентность — «idempotent if the intended effect on the server of multiple identical requests with that method is the same as the effect for a single such request. Of the request methods defined by this specification, PUT, DELETE, and safe request methods are idempotent»; 304 (Not Modified) — «there is no need for the server to transfer a representation», 1xx/204/304 «do not include content»; 401 — «lacks valid authentication credentials». Важно: 429 в RFC 9110 отсутствует (проверено поиском по всей странице — 0 вхождений).
- https://datatracker.ietf.org/doc/html/rfc6585 (WebFetch) — подтверждён 429: «The 429 status code indicates that the user has sent too many requests in a given amount of time», «MAY include a Retry-After header», «MUST NOT be stored by a cache».
- https://datatracker.ietf.org/doc/html/rfc7519 (WebFetch) — подтверждены: JWT «compact, URL-safe means of representing claims», «A JWT is represented as a sequence of URL-safe parts separated by period ('.') characters. Each part contains a base64url-encoded value»; `exp` — «the current date/time MUST be before the expiration date/time»; `jti` — «can be used to prevent the JWT from being replayed»; `iss`/`aud` — «identifies the principal that issued the JWT» / «identifies the recipients that the JWT is intended for».
- https://cheatsheetseries.owasp.org/ (WebFetch, индекс) — подтверждено наличие нужных листов: Session Management, Authentication, SQL Injection Prevention, Cross-Site Request Forgery Prevention, Cross Site Scripting Prevention, Logging, REST Security.
- https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html (WebFetch) — подтверждены: CSPRNG для session ID («A strong CSPRNG… must be used to generate session IDs»), серверное истечение сессий («Session timeout management and expiration must be enforced server-side»), Secure/HttpOnly/SameSite рекомендации, «Treat SameSite as defense in depth against CSRF, not as a replacement for a CSRF token», предупреждение о localStorage.
- https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html (WebFetch) — подтверждены: параметризация как основная защита, «Manually escaping the values into the SQL string is error-prone» (раздел «STRONGLY DISCOURAGED»), allow-list для структурных частей («Parameter markers represent data values, not table names, column names, or SQL keywords such as ASC and DESC»).
- https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html (WebFetch) — подтверждено: сравнение пароля через защищённую функцию сравнения («Returns in constant time, to protect against timing attacks»); хранение паролей перенаправлено на Password Storage Cheat Sheet.
- https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html (WebFetch) — подтверждены: Argon2id/scrypt/bcrypt/PBKDF2 рекомендации, scrypt «minimum CPU/memory cost parameter of (2^17), a minimum block size of 8, and a parallelization parameter of 1», «A salt is a unique, randomly generated string… unique for every user», «Fast hashing algorithms such as SHA-256 are not suitable for password storage».

Не запрошены (курсом не используются): https://expressjs.com и https://www.postgresql.org/docs/ — backend-pro работает на `node:http` с mock-репозиторием; выражений Express и SQL-драйвера PostgreSQL в коде курса нет (проверено по всем 30 решениям). В `sources` курса эти URL не объявлены.

Ни один из запрошенных URL не оказался недоступным. Две страницы (crypto.html — обрезание, AbortController/abort — отсутствие деталей «no-op») отмечены как частично прочитанные; недостающие факты либо взяты с родственных страниц, либо не использовались в новом тексте.
