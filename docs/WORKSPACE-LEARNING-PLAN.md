# DevAtlas workspace and learning flow

Work in the local main checkout. Keep the curriculum authoring work, published content, lesson IDs and existing account progress. No commit, push, deploy, real purchases, or hosted database changes.

1. **Workspace:** Make the desktop sidebar collapsible, preserve the mobile drawer, and add an in-app back action. Keep the catalog as the shared place to choose a course. Removing a course from My courses requires an inline confirmation; the course can be selected again from the catalog. Retire the Notes UI without erasing stored account data.
2. **Day and plan:** Keep the plan for the course outline and My day for work. Show Study or Practice as separate tabs. Require the learner to study and submit the earliest unfinished day before opening a later day; keep historical confirmed days. Paid practice is optional for finishing a day.
3. **Test and interview:** Open one day in Answers & interview. Collect a single submission, allow blanks, and preserve the original result. Every sixth day is timed and includes a written interview. If the lesson has no dedicated written question, use a published quiz question in written format instead of showing its options. Show the score, incorrect answers and unanswered questions. Keep recommended review in Review; distinguish a model-answer match from human evaluation.
4. **Actual progress:** Use saved answers and practice/time records for reports and the graph. A retry in Review must not overwrite the original submitted result. Account sync uses the existing progress document. Browser-stored deadlines and learning checks are for self-study; they are not an anti-cheat service or a server-attested credential.
5. **Subscriptions:** Start keeps starter courses. Pro includes the four courses classified as Pro, practice and AI Tutor. Ultra adds the Expert course and the voice assistant. Names and lists use the catalog; protected course requests consult the existing server membership before returning content. Checkout and payment confirmation use the existing Dodo flow and verified membership. Do not charge a card or alter production configuration for local verification.
6. **Visual checks:** Test navigation, AI Tutor resize and keyboard submit, result persistence, paid access, and the progress graph on desktop and mobile. Keep the landing CTA in the same color and background family as the first section, with a soft blend into the footer.
